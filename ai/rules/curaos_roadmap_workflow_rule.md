# Rice task graph

Rice owns task hierarchy, status, dependencies, specifications, research, decisions and execution links. A forge issue, label or board is integrated provider metadata, never a competing local authority. Use canonical Rice task identities and query the native scoped frontier plus current blocker contexts before dispatch. Unknown blockers remain blocking.

Keep target versions and measurable goal outcomes explicit. Create linked child issues for required dependencies and future issues for unrelated work. Bundle compatible tasks by owning repository, working tree and verification surface. Preserve concrete split reasons. A shipped status needs actual implementation/delivery evidence; a live probe or narrative alone does not prove code landed.

Use the configured toolkit work authoring commands with JSON stdin and Rice CAS/history. Preserve the owning delivery gate, actual review/provenance, hosted requirements and clean default closeout. Do not revive old synchronization scripts or source-local roadmap files.

See [maintained toolkit consumption](../../docs/agents/rice-toolkit.md).
